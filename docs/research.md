# 动动乐园（dongdongpark.com）研究与借鉴说明

> 研究时间：2026-11-14。信息来自官网首页、游戏大全、游戏详情页（freeze / fruit-slash / balloon-keep）与会员页。
> 本文只记录产品层面的观察，代码与美术均为本次重写，没有使用对方任何素材。

## 一句话结论

它把幼儿园里最熟悉的几个肢体游戏（木头人、跳房子、切水果、拔河）搬到摄像头前，用「108 个游戏 + 分龄标签 + 老师教案 + 体测工具」做成一个**面向幼儿园和小学的室内体育内容库**，靠会员订阅收费，靠 SEO 长尾页获客。

真正值钱的不是那 108 个玩法，而是它把「一个网页 = 一节室内体育课」这件事讲清楚了。

## 一、产品拆解

### 1. 形态

- **纯网页**：Chrome / Edge 打开即玩，不装 App、不用手柄，笔记本自带摄像头就够。
- **一个游戏容器 + 内容矩阵**：所有游戏共用一套外壳（倒计时、星级、两人对战、语音引导、暂停、结算），游戏本身只是不同的"关卡"。
- **场景化入口**：不只按年龄分（幼儿园 51 / 小学 102 / 中学 59），还按玩法分（用手、全身、跑跳、安静、动脑、节奏、体能、合作、对战），再按使用场景分（室内体育课、课间十分钟、雨天大课间、体育家庭作业、六一游园会……）。

### 2. 内容（值得注意的设计）

单个游戏页的信息结构非常完整，基本是"给老师和家长看的一页教案"：

1. 一句话玩法 + 别名（"一二三木头人""红绿灯游戏"——都是家长会搜的词）
2. 10 秒**无声演示**（卡通小朋友示范，不用真孩子出镜）
3. 三步玩法
4. **"能练到什么"** 三个标签：自我控制 / 听指令做反应 / 爆发力
5. 游戏信息：适合年龄、运动量（⚡⚡⚡ 出汗）、玩法类型、每局时长、几个人玩、需要什么设备、**拿星标准**（两颗星 ≥ 120 颗星，三颗星 ≥ 190 颗星）
6. "老师、家长怎么用"——直接给课堂编排建议（"一人一局 60 秒，全班轮一圈正好 15 分钟"）
7. 现成教案链接 + 相似游戏

第 4 条和第 6 条是这类产品最容易被忽略、也最能打动付费方的地方：**它不只卖游戏，还卖"这节课怎么上"。**

### 3. 商业模式

| 档位 | 价格 | 主要差异 |
| --- | --- | --- |
| 免费 | ¥0 | 全部游戏可玩（自由玩不限），计分游戏每天 3 局，名单 3 人 |
| 家庭版 | ¥18/月（原价 ¥30） | 不限局数、名单 6 人、2GB 云相册、周报邮件 |
| 班级版 | ¥49/月（原价 ¥69） | 10 个班 × 60 人、班级小报、成绩导出 |
| 学校版 | ¥299/月 | 10 位老师共用名单、可对公、可开票 |

再加一层「能量」点数（超局数多玩几局、AI 成长报告 5 点一份）。典型的教育 SaaS 打法：**免费引流 → 家庭版转化 → 班级/学校版做 ARPU**。

### 4. 技术（从页面行为推断）

- 摄像头 + 浏览器端姿态识别（MediaPipe / TensorFlow.js 一类），画面不上传；
- 首次打开后断网也能玩（说明做了资源本地缓存 / PWA）；
- 中文语音指令贯穿全程（"绿灯，动起来""木头人！"），这是低龄段能玩起来的关键；
- 排行榜、班级名单、云相册需要账号体系，属于增值层。

### 5. 获客

大量「体育教案 + 体测标准 + 场景长尾词」文章（例：《一年级体育跨学科教案〈口算运动会〉》），用内容吃搜索流量，再导到游戏页和会员页。体测评分表/计算器是纯工具，免费，用来换信任和回访。

## 二、我借鉴了什么

| # | 他们的做法 | 这里的落地 |
| --- | --- | --- |
| 1 | **一局 60 秒 + 三颗星** | 三个游戏都是 60 秒、结算给 1～3 星，短到孩子愿意"再来一局"，也方便课堂轮换 |
| 2 | **中文语音当指令**，不只是字幕 | 木头人用语音喊"绿灯，动起来""木头人！"；字幕同步显示，听障或嘈杂环境也能玩 |
| 3 | **每个游戏标注"能练到什么"** | 首页卡片直接挂「抑制控制 / 手眼协调 / 双侧协调」标签，结算页再展开成三条能力条 |
| 4 | **摄像头画面当游戏背景** | 画面调色后铺底，骨骼实时变成剪纸小人叠在上面——孩子看见"自己变成了角色"，代入感比纯动画强 |
| 5 | **给老师/家长的"怎么用"** | 结算页给一句可执行的小提示（"把「木头人」停顿拉长到 4 秒""在弱侧脚下贴条胶带"），而不是只报分数 |
| 6 | **设备自检前置** | 单独的 `check.html`：全身入镜、光线、左右空间三项检查，把"识别不到"的挫败感挡在游戏开始之前 |
| 7 | **免安装 + 画面不出本机** | 姿态模型（wasm + 5.5MB 模型）全部本地化到 `vendor/`，断网可用；没有账号、没有上传、没有排行榜 |

## 三、我刻意没照搬的

1. **不做 108 个，只做 3 个。** 广度是内容库的护城河，但对一个 demo 来说，三个各自打透一种感觉通道的玩法，比十个半成品更能说明产品力。
2. **不做账号、排行榜、云相册。** 这些是订阅制的钩子，也是隐私负担。演示版把数据留在 `localStorage`，符合"幼儿园教室里一台公用电脑"的真实使用场景。
3. **不做营销型长文。** 首页把篇幅让给"为什么这三个动作对感统有用"，用三段解释替代 SEO 矩阵。

## 四、三个 demo 的机制设计

### 1. 木头人（freeze）— 抑制控制

- **输入**：全身运动量（13 个关键点的逐帧位移，按肩宽归一化）。
- **循环**：绿灯 4.6～6.2 秒 → 预警 1.2 秒（黄灯 + "注意——"）→ 红灯 2.6～3.6 秒。
- **得分**：绿灯期间 `运动量 × 7.5/秒` 攒星星，星星从手边飞进计分板。
- **失败**：红灯期间运动量连续 0.26 秒超标 → 被抓，扣一颗心，屏幕红闪 + 印章 + 震动。
- **为什么这样设计**：感统训练里"抑制控制"最难的是**从动到停的那一下**，所以红灯前有 1.2 秒预警，让孩子有机会准备；判定留 0.26 秒容错，避免摄像头抖动误判。
- **难度**：不做难度分级，靠孩子自己"动得更猛 / 停得更快"。

### 2. 水果忍者（fruit）— 手眼协调 / 跨中线

- **输入**：双手腕坐标 + 速度。判定分两档：**手碰到水果就切开**（半径 0.95r），快速划过（≥320px/s）可以隔空切，横跨上一帧到当前帧的线段做相交，快速挥手也不会穿模。
- **循环**：从屏幕下方向上抛水果，出果间隔 0.66s → 0.38s，屏幕上没水果会立刻补一颗。最高点按玩者的肩髋位置算，落在胸口到腰之间——保证够得着，而不是飞到手够不到的地方。
- **得分**：基础 50 分 × 连击倍率（每连一个 +0.1，最高 3 倍）。
- **失败**：**炸弹只有快速划过才会炸**，手放在旁边扫到不算；碰到扣一颗心、断连击。水果掉下去只断连击不扣心。
- **为什么这样设计**：刻意让水果从**对侧**飞过来，孩子必须跨过身体中线去够，这是感统里典型的"跨中线"练习；结算专门统计"跨中线动作"次数。
- **难度**：随时间的自然加速（出果间隔变短），不靠"要求更快的手速"来加难度——那样只会让孩子切不中。

### 3. 节奏跳跳（hop）— 双侧协调 / 前庭觉

- **输入**：髋中心相对基线的横向偏移（±0.52 个肩宽判定左右）、髋部升高或双脚离地判定起跳。
- **循环**：108 BPM 的程序化鼓点，每两拍一个指令（左 / 右 / 跳），光圈从大收拢到箭头，收拢的瞬间就是判定点。
- **判定**：±0.24 秒窗口内状态匹配即命中，±0.11 秒内为「完美」。
- **得分**：完美 120 / 不错 70，连击每层 +3% 倍率。
- **为什么这样设计**：左右交替是最基础的**双侧协调**，起跳刺激**前庭觉**；跟着鼓点做，把"听—动"连接也带上。基准线会缓慢跟随孩子站位漂移，避免站着不动也能一直"命中"。
- **难度**：固定 BPM（换速度会打断节奏感），靠指令组合变难（连续的左右切换、跳跃插入）。

## 五、还可以往下做

- **两人对战**：左右分屏，各自一套关键点，比较星星数（他们的做法，技术上不难）。
- **课堂模式**：名单 + 轮流上场 + 大屏榜单，这才是班级版的真实需求。
- **成长记录**：现在只存了局数和星星，可以把每局的"抑制控制 / 平衡 / 节奏"三条能力值画成周曲线。
- **更多感统动作**：单脚站立计时（前庭）、触觉辨识（屏幕提示摸不同材质）、抛接沙包（本体觉）。
